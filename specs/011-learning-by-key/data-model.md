# Data model: Learning by key

Extends `specs/005-practice-score-library/data-model.md` (shelf, items, levels, exercise definitions) and
`specs/007-library-fidelity-audit/data-model.md` (sources, audit records). Only what changes is listed.

## 1. Entities

| Entity | What it is | Key fields | Source of truth |
|---|---|---|---|
| **Key** | one of the 24 keys | slug, display name, tonic, mode, fifths, circle index, relative key slug, tonic octave (§5) | `src/core/library/exercise/keys.ts` |
| **Key folder** (Section) | `learning/keys/<slug>` | id, title = display name, parent `learning/keys`, order = circle index, description | generated by `tools/library/sections.ts` from Key |
| **Key-change folder** (Section) | `learning/key-changes/<from>-to-<to>` | id, title "C major -> A minor", description "relative" / "parallel", order | generated from the key-pair table (§3) |
| **Step** | position of an item in a folder | `step` (introduction, beginner, intermediate, advanced, song), `stepOrder` | item sidecar (library-index 1.2) |
| **Step exercise** | the main generated item of a step | `stepOrder` 0, level = step | exercise definitions `step-*.json` |
| **Extra** | an existing drill kept at a step | `stepOrder` >= 10 | moved exercise definitions |
| **Song** | public-domain melody + our chords | source id, melody selection, shelf key, chord plan, level | `content/library/songs/*.json` (song-definition 1.0) |
| **Successor link** | old id -> new item | `supersedes: [{id, hash}]` in the new sidecar | `tools/library/successors.ts` (§7) |
| **Section alias** | old section id -> new | `formerIds` on the new section | `tools/library/sections.ts` |
| **Level** | + `introduction` | caps per criterion (§4) | `src/core/defaults.ts` |
| **Fact** | + `chordChangesPerBar` | number | `src/core/library/facts.ts` |

## 3. Key pairs

| From | To | Relation | Pivot (Introduction/Beginner) |
|---|---|---|---|
| C major | A minor | relative | IV = VI (F), then E (V of A minor) |
| A minor | C major | relative | VI = IV (F), then G (V of C) |
| C major | C minor | parallel | V (G) shared; new signature (3 flats) at the arrival bar |
| C minor | C major | parallel | V shared; 3 naturals (`<cancel>`) at the arrival bar |
| G/E minor, F/D minor, D/B minor | ... | relative | same pattern |
| G/G minor, F/F minor, D/D minor, A minor/A major | ... | parallel | same pattern |

## 4. Levels and checks

Introduction caps (added to every `LEVEL_*` record in `src/core/defaults.ts`; Beginner shown for comparison):

| Criterion | Beginner | Introduction |
|---|---|---|
| 1 pitch span (semitones) | 36 (exercises 38, D-2 B7) | 36 |
| 2 bounds MIDI | 36-84 (exercises 35-85) | 36-84 |
| 3 hand independence (B1 metric) | 0.35 | 0 |
| 4 voices per staff | 1 | 1 |
| 5 shortest value (beats) | 0.5 | 1 |
| 6 longest run at shortest value | 4 | 4 |
| 7 tempo qpm | 50-100 | 50-72 (kept inside Beginner's range so the caps nest) |
| 8 tempo changes | 0 | 0 |
| 9 key fifths (pieces) | 2 | 1 |
| 10 key changes | 0 (key-change exercises 1, D-2 B6) | 0 (key-change exercises 1) |
| 11 accidentals per 16 bars | 2 (exercise leading tone/6th exempt, D-2 B5) | 2 (same exemption) |
| 12 metres | 4/4, 3/4, 2/4 | 4/4, 3/4 |
| 14 bars | 8-32 | 8-16 (kept inside Beginner's range; the minimum does not apply to exercises anyway) |
| 15 duration (s) | 90 | 60 |
| 16 largest interval one hand | 9 | 7 |
| 17 largest leap | 12 | 12 |
| 18 / 19 mean / peak density | 2.5 / 5 | 1.5 / 3 |
| 20-25 ties, tuplets, grace, ornaments, repeats, pedal | limited | none |

Hand independence (criterion 3), after D-2 B1: a bar counts as independent when the onset-tick sets of staves 1 and 2
are both non-empty and **neither is a subset of the other**.

`chordChangesPerBar`: for each staff, the chord attacks (onsets with 2+ sounding notes of that staff starting together)
whose pitch set differs from the previous chord attack of that staff; summed over staves, divided by written bars.

**Step order** (`checkStepOrder`, FR-010): over the main items (step introduction/beginner/intermediate/advanced with
`stepOrder` 0; songs never take part) of one folder in step order, for each consecutive pair
(a, b): `tempoBpm`, `notesPerBeat`, `handIndependenceFraction`, `chordChangesPerBar` of b >= a, and at least one >.
Failure message: `learning/keys/f-sharp-major: intermediate is less demanding than beginner on notesPerBeat (2.4 < 2.5)`.

## 5. Register rule (pattern and key-change forms)

- T = the right-hand scale tonic: octave 4 for C, Db, D, Eb, E, F (and their minors); octave 3 for F#, G, Ab, A, Bb, B.
- RH scale T..T+12; LH scale T-12..T.
- Chords: the bass of every chord is the unique pitch of its bass pitch class in the window [anchor-7, anchor+4], where
  the anchor is the root of the tonic chord in that hand: T-12 in the left hand, T+12 in the right. So I is rooted at the
  anchor, IV and V below it (F2 and G2 in C major), ii and iii just above, and every inversion sits beside its root
  position; the other notes stack upward in close position. (The first draft chose the voicing nearest to the previous chord;
  it drifts upward through I-I6-I64, so the fixed window replaced it.)
- Span: I/V only (Introduction) T-17..T+19 = 36; with IV T-19..T+19 = 38 (hence D-2 B7). F# major sits at the edge of
  bounds 35-85; the generator's range guard fails the build rather than moving one key.

A *moved* item keeps its music; its new sidecar lists `supersedes` with the old id and the old file hash (the bytes may
be identical, in which case adoption is a no-op). Moved drills keep their existing level and are exempt from the step-
order check (not main items).

## 8. Validation (additions to 005 §3)

| Rule | On violation |
|---|---|
| Item under `learning/keys|key-changes` has `step`; `(step, stepOrder)` unique per folder | index refused |
| Key folder has main introduction, beginner, intermediate, advanced; key-change folder main introduction, beginner, intermediate | index refused |
| Step order (§4) | index refused, message names folder, steps, fact |
| `supersedes[].id` unique across the shelf and not a shelf id | index refused |
| Song source approved and melody cross-check clean | `library:songs` refuses to write |
| Song chords match names and allowed set | fidelity check fails |

## 9. State: library panel (session only)

`openFolders: Set<sectionId>` in `libraryState`, initialised from the default rule (library-port 1.2 §2) on first index
load; toggled by the user; when a filter is active the rendered open set is "folders with matches" and the user set is
left untouched for when the filter clears.
